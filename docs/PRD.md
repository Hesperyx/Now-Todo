## 主题

**面向个人用户的 Android/iOS 开源免费离线 Todo 应用**

- 文档类型：产品需求文档（PRD）

## 简介

本产品是一款面向个人用户的跨平台 Todo 应用，基于 Flutter 开发，支持 Android 与 iOS。产品坚持本地离线优先、无账号体系、无广告、无强制付费，采用 MIT 许可证开源，并通过自愿捐赠支持持续维护。

首版将覆盖任务管理、清单分类、标签、优先级、截止日期、本地提醒、子任务、重复任务、搜索筛选、深色模式、数据导入导出等核心能力。桌面小组件、日历视图、统计面板、多语言、无障碍优化等作为增强项，按迭代节奏推进。

核心功能不依赖网络。用户数据默认存储在本地设备，用户可通过导出文件自行备份和迁移。

## 问题陈述

个人 Todo 工具市场存在以下典型问题：

1. **功能臃肿**：许多产品叠加项目管理、协作、AI、笔记等复杂能力，个人用户学习成本高。
2. **订阅疲劳**：基础提醒、标签、主题、同步等功能常被放入付费墙。
3. **隐私担忧**：任务内容、日程和个人习惯属于敏感数据，部分用户不愿上传云端。
4. **离线体验差**：网络不稳定时无法正常新增、编辑或查看任务。
5. **数据锁定**：导出能力弱，用户难以备份、迁移或长期保存自己的数据。
6. **开源选择有限**：同时满足跨平台、离线优先、界面现代、功能完整、可持续维护的开源 Todo 应用较少。
7. **广告干扰**：免费产品常通过广告或推荐内容干扰核心任务流程。

因此，本产品希望为个人用户提供一个免费、开源、离线、隐私友好、功能完整且可自行备份的 Todo 工具。

## 用户故事

### 个人用户

1. 作为忙碌职场人士，我希望快速新增任务并设置截止日期，以便不错过重要事项。
   **验收标准**：首页可快速新增；支持标题、日期、优先级；保存后立即出现在列表中。

2. 作为学生，我希望按清单或课程分类任务，以便区分作业、考试和个人事务。
   **验收标准**：支持创建清单；任务可归属清单；可按清单筛选。

3. 作为自由职业者，我希望给任务添加标签和优先级，以便安排当天工作重点。
   **验收标准**：支持多标签；支持高/中/低优先级；支持排序和筛选。

4. 作为经常外出的用户，我希望应用在无网络时也能正常使用，以便随时记录任务。
   **验收标准**：新增、编辑、删除、完成、搜索、提醒均不依赖网络。

5. 作为隐私敏感用户，我希望任务默认只保存在本地，以便不担心数据被上传。
   **验收标准**：无账号也可使用；默认无云端上传；无强制追踪。

6. 作为长期用户，我希望导出和导入数据，以便换机或备份。
   **验收标准**：支持 JSON 全量导出；支持从导出文件恢复；格式有版本号。

7. 作为有重复事务的用户，我希望设置重复任务，以便自动生成周期任务。
   **验收标准**：支持每天、每周、每月、自定义重复；可编辑和结束重复。

8. 作为任务较多的用户，我希望使用子任务拆分步骤，以便逐步完成复杂事项。
   **验收标准**：任务下可新增子任务；子任务可勾选完成；父任务展示进度。

9. 作为夜间使用者，我希望支持深色模式，以便减少视觉疲劳。
   **验收标准**：支持浅色、深色、跟随系统。

10. 作为开源支持者，我希望在应用内看到开源许可证和捐赠入口，以便支持项目发展。
    **验收标准**：关于页展示 MIT 许可证；捐赠入口自愿、外链、不绑定功能。

11. 作为社区贡献者，我希望项目结构清晰、文档完整，以便提交 Issue 或 PR。
    **验收标准**：仓库包含 README、贡献指南、行为准则、开发说明和基础 CI。

## 技术需求

### 客户端技术栈

- 框架：Flutter 稳定版。
- 支持平台：Android 8.0+、iOS 14+。
- 状态管理：Riverpod / Bloc / Provider 中选型一种并保持统一。
- 路由：go_router 或同类方案。
- 本地存储：SQLite + Drift / Isar / Hive 中优先选择适合关系型查询和迁移的方案，建议 SQLite + Drift。
- 通知：flutter_local_notifications 或同等方案，结合 timezone 处理本地提醒。
- 文件导入导出：file_picker、share_plus、path_provider 等。
- 测试：单元测试、Widget 测试、集成测试。
- CI：GitHub Actions，执行格式化、静态分析、测试和构建检查。

## 开发风险

1. **范围蔓延风险**
   “MVP 越全越好”容易导致首版周期失控。建议明确核心范围，增强项放入后续迭代。

2. **平台差异风险**
   Android 与 iOS 在通知权限、后台限制、文件访问、小组件能力上差异较大，需预留原生适配成本。

3. **本地通知风险**
   用户拒绝通知权限、系统省电策略、时区变化、重复提醒规则均可能影响提醒可靠性。

4. **数据丢失与迁移风险**
   本地离线存储虽保护隐私，但设备丢失、卸载、系统清理可能导致数据丢失。必须提供导入导出和明确备份提示。

5. **导入导出兼容风险**
   文件格式、版本升级、字段变更可能导致旧备份无法恢复。需要版本号和迁移策略。

6. **开源维护风险**
   MIT 允许广泛使用，但项目长期维护依赖贡献者和捐赠，可能出现维护动力不足。

7. **捐赠合规风险**
   iOS App Store 对捐赠和外部支付链接有审核限制。首版需谨慎设计捐赠入口，必要时按平台差异化处理。

8. **隐私合规风险**
   即使无账号，也需准备隐私政策，明确不采集任务内容、不强制联网、不默认追踪。

9. **重复任务与提醒复杂度风险**
   重复规则、截止日期、完成状态、提醒时间组合复杂，容易产生边界 Bug。

10. **社区贡献质量风险**
    开源项目需要贡献指南、代码规范和评审机制，否则代码质量可能下降。

## 结论

本 PRD 定义了面向个人用户的 Android/iOS 开源免费离线 Todo 应用的首版方向。产品以 Flutter 开发，坚持本地离线优先、无账号、无广告、无付费墙，采用 MIT 许可证，并通过自愿捐赠支持长期维护。

首版应优先交付完整可用的个人任务管理闭环：任务增删改查、清单、标签、优先级、截止日期、本地提醒、子任务、重复任务、搜索筛选、深色模式、JSON 导入导出、开源许可证与捐赠入口。桌面小组件、日历视图、统计面板、多语言、无障碍等可作为增强项迭代。

项目成功的关键在于：控制 MVP 范围、保证本地数据安全、处理 Android/iOS 差异、遵守应用商店与隐私合规要求，并建立可持续的开源社区与捐赠机制。建议下一步进入需求评审、原型设计、技术方案确认和里程碑排期。
